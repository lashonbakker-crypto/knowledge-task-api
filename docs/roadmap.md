# 24 个月成长路线

这是学习与迭代目标，不是已经完成的能力。每个阶段保留自己的实现、失败案例、实测结果和讲解记录。时间可以调整，验收标准不能靠 AI 的文字判断替代。

| 阶段 | 主要任务 | 应交付的证据 |
| --- | --- | --- |
| 1–2 月 | Python 类型、异常、虚拟环境；HTTP、JSON、SQL基础；跑通首版 | 自己从空文件写一个鉴权接口和测试；解释一次请求经过哪些函数 |
| 3–4 月 | 理解事务、索引、并发、幂等和租约 | 复现重复提交、旧 worker 写回和取消竞态；自己新增能失败的回归案例 |
| 5–6 月 | 提炼存储接口，迁移 PostgreSQL | 同一业务与故障测试在两种存储通过；验证行锁领取与提交 fencing |
| 7–8 月 | 独立 worker、部署、日志、指标与链路追踪 | 进程重启实验；记录队列等待、执行时间和错误率，附配置和原始结果 |
| 9–10 月 | 学习 Agent 的模型、工具调用、状态与停止条件 | 经明确配置后接入真实模型；限制工具、轮次、时间和费用，区分真实调用与测试替身 |
| 11–12 月 | 检索实验：中文分词、向量、混合检索 | 自建来源合法的数据集和固定查询；报告 Recall@K、失败例和测试集边界 |
| 13–14 月 | Agent 评测与输入边界 | 固定工具调用轨迹、来源引用和拒绝策略；恶意文档不能改变工具权限 |
| 15–16 月 | 缓存、配额、公平调度与背压 | 多用户负载，验证一个用户不能吃光容量；缓存键包含租户与版本 |
| 17–18 月 | 做一个真实的小规模用户试用 | 用户授权、真实反馈、错误修复；只保存必要数据，不把试用称作大规模生产 |
| 19–20 月 | 备份恢复、迁移、异常恢复与版本兼容 | 从备份还原服务；注入存储 / 进程故障；旧客户端与新版本的兼容记录 |
| 21–22 月 | 选一个实测瓶颈做优化 | 相同硬件、数据、并发和预算下的前后对照；保留原始测量和质量检查 |
| 23–24 月 | 整理简历、设计文档和面试演示 | 一条命令演示；10 分钟讲架构；不看 AI 回答故障、事务和取舍问题 |

## 本版与后续

本版新增了只读工具适配器（参见 [03-agent-tool-bridge](03-agent-tool-bridge.md)），仅包含受控检索/原文读取，不等于模型调用、Agent 编排或工具权限管理。

本版已实现：本地文档入库、词法检索、任务持久化、幂等、有限重试、租约 fencing、心跳续租、Python 处理器入口、单调时钟预算与协作中断、取消、事件回放、SSE、身份边界和行为测试。它是学习起点。

后续待实现：PostgreSQL、强制进程终止与资源隔离、任务公平性、限流与配额、账号与 token 生命周期、中文 / 向量检索、模型生成、完整 Agent、工具权限与预算、评测集、部署与可观测性、数据保留与迁移。

## 使用 AI 的方式

可以让 AI 帮你解释、生成反例、检查代码和找官方文档，但每个里程碑至少做三件事：预测运行结果、自己复现故障、口头解释最终改动。遇到看不懂的接口，先补基础再继续叠功能。

每月选一项核心功能，不看源码重新写一次最小版本。提交里记录自己的判断与验证。不要为了获得更多 commit 数量而改措辞，也不要把未运行的示例、未来目标或 AI 初始代码写成自己的已完成业绩。
